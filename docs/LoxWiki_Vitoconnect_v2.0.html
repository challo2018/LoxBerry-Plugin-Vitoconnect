1. Übersicht & Highlights der Version 2.0

Das Viessmann Vitoconnect LoxBerry Plugin bindet Viessmann Heizungsanlagen (Gas-, Öl- und Pellet-Brennwertgeräte, Wärmepumpen sowie Hybrid-Systeme mit Vitoconnect 100/200 oder integriertem WLAN-Modul) nahtlos an den Loxone Miniserver an.

Mit der Version 2.0 wurde das Plugin von Grund auf modernisiert und basiert nun auf der bewährten Python-Bibliothek PyViCare:

  • Moderne PyViCare-Architektur: Schneller, stabiler und ressourcenschonender Hintergrunddienst mit automatischer OAuth2-Token-Erneuerung (keine Verbindungsabbrüche mehr).
  • Vollständige Bidirektionale Steuerung über MQTT: Betriebsmodi (z. B. heating, dhwAndHeating, standby), Raum- und Solltemperaturen sowie Warmwasser-Einmalladung können direkt aus Loxone über intuitive vitoconnect/set/... Topics gesteuert werden.
  • Dynamische Parameter & Constraints: Das Plugin ermittelt erlaubte Betriebsmodi, Min/Max-Temperaturgrenzen und Schrittweiten live und anlagenspezifisch direkt aus der Viessmann API.
  • Automatisches API-Quota-Management: Schützt den Viessmann-Account zuverlässig vor Sperren durch das 1.450 Calls / 24h Tageslimit.
  • LoxBerry Design System (LoxBerry DS): Neues, modernes Webfrontend mit Dark-Mode-Unterstützung, Live-Statistiken, interaktivem Testpanel und Datenpunkt-Suchfunktion mit 1-Klick-Kopierbuttons für Loxone Config.
  • 1-Klick-Bibliotheks-Updates: PyViCare kann bei API-Änderungen durch Viessmann direkt über die Weboberfläche aktualisiert werden.
Hinweis für Umsteiger von Version 1.x:
Die veralteten HTTP-Ausgangsbefehle (vitoconnect.php?action=setvalue) und Cronjobs entfallen vollständig. Die gesamte Kommunikation erfolgt modern, schnell und eventbasiert über das LoxBerry MQTT Gateway.

2. Voraussetzungen & Viessmann Developer Portal Setup

Für die Nutzung des Plugins ist ein kostenloser Entwickler-Zugang bei Viessmann erforderlich:

  1. Registriere dich mit deinem bestehenden ViCare-Konto im Viessmann Developer Portal (https://developer.viessmann.com/).
  2. Navigiere im Menü auf API Keys und klicke auf Create API Key.
  3. Vergib einen beliebigen Namen (z. B. LoxBerry Vitoconnect).
  4. Sehr wichtig – Redirect URI: Trage als Redirect URI exakt folgende Adresse ein:
    vicare://oauth-callback/everest
  5. Sehr wichtig – Google reCAPTCHA: Wähle bei reCAPTCHA zwingend Disabled aus (da LoxBerry im Hintergrund läuft und kein Captcha lösen kann).
  6. Klicke auf Save und kopiere die generierte Client-ID (API-Key).
Achtung:
Wird die Redirect URI abweichend eingetragen oder reCAPTCHA aktiviert gelassen, kann sich das Plugin nicht bei Viessmann authentifizieren!

3. Konfiguration im LoxBerry

Öffne im LoxBerry die Weboberfläche des Vitoconnect-Plugins unter Plugins → Vitoconnect → Settings:

3.1 Viessmann Account & API

  • E-Mail (Benutzername): Deine E-Mail-Adresse des ViCare Accounts.
  • Passwort: Dein Passwort des ViCare Accounts.
  • Client-ID (API-Key): Die im Viessmann Developer Portal erstellte Client-ID.

3.2 Abfrage-Intervall & Quota-Schutz

Viessmann erlaubt für Privatanwender maximal 1.450 API-Aufrufe pro 24 Stunden. Das Plugin berechnet das Kontingent automatisch und bietet folgende Intervalle:

  • 120 Sekunden (Empfohlen): Entspricht ~720 Aufrufen/Tag. Bietet perfekte Aktualität und lässt 50 % Reserve für Steuerbefehle.
  • 180 Sekunden (3 Minuten): ~480 Aufrufe/Tag (ideal bei mehreren Heizkreisen/Geräten).
  • 60 Sekunden (1 Minute): ~1.440 Aufrufe/Tag (Achtung: kaum Reserve für Steuerbefehle).

3.3 MQTT Gateway Konfiguration

Das Plugin liest die Verbindungsdaten des LoxBerry MQTT Gateway Brokers automatisch aus. In den Einstellungen muss lediglich festgelegt werden:

  • MQTT aktivieren: Schalter auf Ein.
  • Basis-Topic: Standard ist vitoconnect (der Miniserver empfängt Werte unter vitoconnect/#).
  • Multi-Device Topics:
    • Aus (Standard / Abwärtskompatibel): Hauptheizgerät publiziert direkt unter vitoconnect/... (kompatibel zu Loxone Config v1.x).
    • Ein: Bei mehreren Geräten oder Wärmepumpen-Kombinationen erhält jedes Gerät sein eigenes Präfix (z. B. vitoconnect/device_0/... und vitoconnect/device_1/...).

4. Monitoring, Live-Werte & Testpanel

In der Registerkarte Query links & Data stehen umfangreiche Diagnose- und Steuerwerkzeuge zur Verfügung:

  • Dienst- & Quota-Monitor: Zeigt den Online-Status des Hintergrunddienstes, die verbleibenden API-Aufrufe der letzten 24h sowie den Zeitstempel des letzten Abrufs in Echtzeit.
  • Interaktives Testpanel: Ermöglicht das Testen von Steuerbefehlen (Betriebsmodus, Sollwerte, Warmwasser-Push) direkt im Browser mit sofortiger Erfolgsmeldung, bevor die Logik in Loxone Config programmiert wird.
  • Live-Datenpunkte: Vollständige Tabelle aller von der Heizung bereitgestellten Werte. Über das Suchfeld kann nach Begriffen wie Vorlauf, Brenner oder HK0 gefiltert werden. Ein Klick auf [Kopieren] übernimmt das exakte MQTT Topic in die Zwischenablage.

5. Einbindung in Loxone Config (Schritt für Schritt)

5.1 Voraussetzungen in Loxone

Stelle sicher, dass im LoxBerry MQTT Gateway Plugin das Topic vitoconnect/# abonniert (subscribed) ist. Das LoxBerry MQTT Gateway überträgt die Werte automatisch als virtuelle HTTP-Eingänge oder MQTT-Eingänge an deinen Miniserver.

5.2 Werte empfangen (Virtuelle MQTT-Eingänge)

Für jeden gewünschten Wert legst du in Loxone Config unter Virtuelle Eingänge einen neuen Eingang an:

  • Bezeichnung: Das jeweilige MQTT Topic, z. B. vitoconnect/circuit_0/room_temperature
  • Datentyp: Bei analogen Werten (Temperaturen, Druck) den Haken „Als Digitaleingang verwenden“ deaktivieren. Bei Statusmeldungen (Brenner aktiv, Pumpe) als Digitaleingang verwenden.
  • Texteingänge: Für den Betriebsmodus oder Fehlercodes einen Virtuellen Texteingang (VIT) mit Topic vitoconnect/circuit_0/mode verwenden.

5.3 Heizung aus Loxone steuern (Virtuelle Ausgänge)

Um Werte an Viessmann zu senden, legst du in Loxone Config einen Virtuellen Ausgang an:

  1. Erstelle einen Virtuellen Ausgang mit der Adresse des MQTT Brokers (oder nutze das MQTT Gateway).
  2. Füge einen Virtuellen Ausgangsbefehl hinzu:
    • Befehl bei EIN: Sende an das gewünschte vitoconnect/set/... Topic mit dem gewünschten Wert.

Beispiele für Steuerbefehle:

Steuerziel MQTT Set-Topic Mögliche Werte / Payload
Betriebsmodus HK 0 vitoconnect/set/circuit_0/mode heating, dhwAndHeating, dhw, standby, cooling
Normal-Solltemperatur vitoconnect/set/circuit_0/normal_temperature Zahl, z. B. 21.0 oder 22.5
Komfort-Solltemperatur vitoconnect/set/circuit_0/comfort_temperature Zahl, z. B. 23.0
Absenk-Solltemperatur vitoconnect/set/circuit_0/reduced_temperature Zahl, z. B. 17.5
Warmwasser-Sollwert vitoconnect/set/dhw/target_temperature Zahl, z. B. 55.0
Einmalige WW-Bereitung (Push) vitoconnect/set/dhw/one_time_charge start / 1 (Aktivieren) oder stop / 0 (Stoppen)
Sofortige API-Abfrage (Poll) vitoconnect/poll 1 (triggert sofortigen Datenabruf ohne Warten auf Intervall)
Tipp für Loxone Statusbausteine:
Verbinde den virtuellen Texteingang vitoconnect/circuit_0/mode mit einem Loxone Status-Baustein, um den Betriebsmodus in der Loxone App als Klartext (z. B. „Nur Heizen“, „Heizen & Warmwasser“, „Standby“) darzustellen und über Radiobuttons oder Auswahltasten direkt umzuschalten.

6.2 Erweiterte Viessmann-Features (Generic Property Topics)

Zusätzlich zu den Standardpunkten erkennt das Plugin automatisch alle von Viessmann gemeldeten Eigenschaften deiner Heizung und publiziert sie unter vitoconnect/features/... (z. B. vitoconnect/features/heating/circuits/0/heating/curve/slope). Diese sind in der Weboberfläche unter Live-Datenpunkte gelistet und inklusive aller Wertebereiche schreibbar!

7. Häufige Fragen & Fehlerbehebung (FAQ)

Frage: Warum erhalte ich Fehlermeldungen bezüglich Quota / 429 Too Many Requests?
Antwort: Viessmann begrenzt Entwickler-Accounts streng auf 1.450 Aufrufe pro 24 Stunden. Stelle das Abfrageintervall in den Einstellungen auf mindestens 120 Sekunden. Sollte das Kontingent überschritten worden sein, pausiert der Dienst automatisch, bis wieder Freikontingent verfügbar ist.

Frage: Warum wird ein bestimmter Betriebsmodus bei mir nicht angezeigt?
Antwort: Die verfügbaren Betriebsmodi unterscheiden sich je nach Heizungsmodell (z. B. Wärmepumpe mit heating oder Gas-Brennwert mit dhwAndHeating). Das Plugin liest die zulässigen Modi dynamisch aus der Viessmann API aus. Es werden exakt die Modi angeboten, die deine Heizung unterstützt.

Frage: Wo finde ich ausführliche Logdateien?
Antwort: Im LoxBerry Webfrontend unter Log-Dateien → vitoconnect. Dort kann die Protokollierung auf DEBUG umgeschaltet werden, um detaillierte Informationen zur Kommunikation mit der Viessmann Cloud einzusehen.
